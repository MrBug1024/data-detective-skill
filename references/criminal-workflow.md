# 刑侦模式：从现场到可检验的侦查方向

读取本文件后，按涉及的物证/概率问题读取 forensic-science.md；涉及行为、空间、假说比较时读取 investigation-methods.md。不把本文件当案件答案。

涉及目击描述、面部特征、模糊/遮挡影像或绘制合成画像时，转到 [facial-composites.md](facial-composites.md)。行为/心理假说与容貌材料分开，不能将侦查假说画进脸；画像结果仍需独立取证。

## 1. 建立案件边界和证据账本

先明确要区分什么：是否发生犯罪、事件如何发生、痕迹来自何物、谁实施某行为，还是优先保护/保全什么。不要把“找到嫌疑人”当唯一出口。现场即时危险、受害人救助、易灭失证据先进入行动计划。

为原始材料分配唯一 evidence_id。每条记录保存原文、位置、观察/转述/专家意见类别、采集时间、观察时间、来源人员、原件/复制件、保管链、污染风险、测量方法和误差；不知道填 unknown/null。把相同上游来源归为依赖组；不同文本或文件不是独立性证明。

脚本提取的日期只叫“原文时间声明”。校准监控/门禁/手机/服务器的时区、夏令时、漂移、网络延迟；分别保存原始时间与校正区间、校正依据。不能用不确定时钟做精确不在场认定。相同时间保留多个事件与来源，不覆盖。

校时后必须联合检查同一人的全部时空约束：每段取最早可能离开、最晚允许到达，与有依据的最短行程比较。即使按最宽时间余量也来不及，应记录“在来源、身份、时钟及行程下界均成立条件下不相容”，先复核这些前提；不能挑一份记录机械判真，或把不相容反写为身份已确认。可用 [timeline_checks.py](../scripts/timeline_checks.py) 做区间算术，具体规则见 [时间、空间与身份的联合约束](investigation-methods.md#时间空间与身份的联合约束)。

## 2. 先做关键观察与竞争解释

写出少量最能区分解释的观察，分别标注已经验证/有争议/未验证。摘要足够复核即可，不输出冗长内部思维。

按争议命题构建竞争假说（通常 2–4 个有实质差异的解释，数量由案情决定）：主动实施、无关/合法接触、二次转移/污染、记录或测量误差、尚未提出的其他解释。不是机械地为每案塞满这些假说；避免仅比较几名先被怀疑的人而排除无人犯罪的可能。

每组先固定一个待区分命题、层级及共同背景，再选择少量可区分的备选。检查是否有假说包含另一假说，或将“合法来源、二次转移、与事件无关”等可独立成立的命题捆成故事；有则拆成不同问题的子命题分别检验。不能因一个子命题成立就支持整段复合故事；不要求所有问题共用一组假说。

每个假说给出：命题层级、能解释的证据、反证、必须依赖的假设、最难解释之处、决定性缺口。已知材料不足以区分时保持并列，不按描述生动程度排名。

## 3. 证据比较与推断

建立 evidence × hypothesis 的 ACH 矩阵：支持/反对/中性/未知 + 引用 + 简短依据。优先检验强矛盾、来源可靠性和能改变排序的证据；不按支持格数量选胜者。检查同源重复、失效测量、场景假设和缺失证据的可检出条件。

- IBE：在可比证据覆盖下比较解释力、额外假设和替代解释；不是逻辑证明。
- LR：先写两个命题和背景条件，再找适用的验证模型。没有条件概率就保留定性；不能凭直觉填数字。必要时 `scripts/forensic_math.py` 仅算术校验，不生成 LR。请求后验时说明互斥且穷尽的命题、先验依据和敏感性，不将痕迹来源概率叫有罪概率。
- 足迹/工具痕/DNA/数字日志：明确检验对象及限制；类别相容不等于唯一同一。检验保管/转移/时间信息后才讨论活动层。
- 心理/行为：只写可观察行为和多种动机假说，保留情境、机会与个体差异；不能诊断人格或把行为画像当身份识别器。

## 4. 将推断变成原子调查动作

优先列 3 项，完整计划按需扩展。每项必须包含：

| 字段 | 内容 |
|---|---|
| action_id / action | 一个明确动作、对象和输出物，例如调取某设备原始视频及校时日志 |
| priority | urgent/high/normal，附排序理由：灭失性、区分度、可行性、成本/时间 |
| evidence_ids / hypothesis_ids | 解决哪些证据问题、区分哪些解释 |
| expected_results | 至少两个竞争解释下分别预期看到什么；结果应可观察 |
| decision_rule | 哪种结果增强/削弱哪个命题；无法观测/阴性是否有意义 |
| prerequisites / feasibility | 所需授权/专家/设备、材料、预计工作量；未知就说未知 |
| preservation | 完整性、采样对照、防污染和记录要求（适用时） |
| stop_or_update | 何时停止该路径或按新证据重排 |

“继续调查/查监控/加强心理分析”不足以执行。例：采集足迹带比例尺与垂直拍照、记录基底/变形、提取可比鞋样并由合格检验人员盲比；预期类别差异可排除某鞋，相容仍不能确认穿鞋人。不能让执行动作损坏未保全证据。

逐项复核行动的每种可观察结果与**假说完整命题**的关系：支持、削弱或 `uninformative`（无鉴别力），写出受影响的子命题与仍未解决的部分。确认来源不等于确认活动；未识别人、结果缺失或各假说同样预期的结果不能自动增强/削弱完整命题。将更新规则与ACH同一假说逐字对照，防止支持方向写反；结果预期仍须具体，不能只写“支持H1/削弱H2”。

每个结果格只描述一种状态，把“取得失败”“已检查未检出”“检出可识别信息”分别写出。取得失败、未检查或检出能力未知应为 `uninformative`；阴性只有在相关范围已覆盖、预期可留存且检出能力足够时才可评价为反证。证据意义限定到所指时间、地点、对象和命题层级；同源材料不排除未检查处另有独立观察，别时别处的出现不自动支持本次具体活动。

## 5. 输出与迭代

完成报告按 schemas/criminal-analysis.schema.json 保存；场景简单时正文可以简短，但关键引用、替代解释、首要动作不能省略。将最终分析与脚本原始 packet 分开。

输出前，对可能改变调查方向的身份排除、不在场认定、活动层推断及支持/削弱方向执行一次定向复核。有可用独立 reviewer 时，只提供相关原始证据、适用参考和待审报告，不给预期答案，要求独立核对命题、时空约束及更新方向；无可用 reviewer 时，Agent 逐命题重新对照原始证据，并注明“未获独立复核”。将发现的问题修正后再交付；该步骤不保证判断正确，也不要求低影响细节逐条双审。

保存后运行 `python scripts/validate_analysis.py analysis.json` 检查 Schema、ID唯一性、引用和ACH覆盖。该检查不能判断引文是否真的支持结论，仍须复核证据含义与行动可行性。

- 当前判断：可支持到哪一层；不能区分什么。结论用 observed/provisional/undetermined/refuted，避免未检验的“confirmed”。
- 证据账本：含来源与依赖分组，保留未知。
- 竞争假说与 ACH：列实质反证/缺口；没有反证不等于假说成立。
- 调查计划：按优先级、可行性、鉴别价值排列，给结果更新规则。
- 限制与复核：材料覆盖、未校时、未验证模型、来源依赖、画像限制；新增材料后记录哪个判断因哪条证据改变。

终止条件：已达到用户调查目的且关键争议被独立可复核材料解决；或现有材料无法进一步区分且下一步依赖外部行动。后者仍交付“未定 + 有序补证计划”，不能填补成确定嫌疑人。

## 6. 速度与质量

先读场景/原始证据摘要，再查决定推断的参考；不全库铺开检索。并行处理独立证据组，汇总时检查依赖。只对最能改变方向的假说做下一轮查证。材料少且争议明确时，一张小矩阵 + 三项动作足够。复杂并不意味着输出越长越好。
