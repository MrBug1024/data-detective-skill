# 面部合成画像：证据受控流程

本模块把目击描述或影像中实际可见的面部特征转成可核查的示意图，帮助提出下一步取证问题。输出是**合成示意图，不是现场照片，也不证明身份或罪责**。NIJ 的目击证据指南将合成画像定位为发展调查线索的工具，而非独立证据。[NIJ, 1999, 第 II 节](https://www.ojp.gov/pdffiles1/nij/178240.pdf)

下文的特征台账、出图门槛、版本规则和验收指标是本 skill 的操作设计；不是已验证的画像算法，也不是某机构对本 skill 的认证。真实案件中的正式证人访谈、辨认和对外发布应由有相应权限、训练的人员按当地程序进行。

## 1. 先判断材料能支持什么

| 输入材料 | 可以输出 | 不能据此输出 |
|---|---|---|
| 直接看见面部的证人，保有独立、原始描述 | 描述台账；在信息充分时，按该证人的记忆制作示意图 | 把证人确信程度当作准确率；把主观描述当成测量 |
| 有来源的清晰照片或视频 | 对实际可见区域的描述、标注或描摹；保留遮挡和视角 | 认定画面人物就是作案者；凭外貌判断心理、人格或罪责 |
| 短时、远距、暗光、遮挡或模糊影像 | 可见特征清单、未知区域、需要寻找的其他机位 | 为眼睛、鼻形、疤痕等未辨明部位补出“清晰真相” |
| 只有现场、犯罪方式、脚印、行为、职业或心理假说 | 下一步寻找目击、原始影像等面部材料的计划 | 据此画出个体的五官、肤色、祖源或“凶相” |
| 只有祖源信息或 DNA 分析摘要 | 原样引用报告的限定结论，提出交由合资格实验室解释的需求 | 将祖源类别或表型概率渲染为某个人的真实脸 |

DNA 表型推断中的某些色素特征与完整面部形态预测不是同一能力。不要把有条件的眼色、发色等实验室预测，扩写为个体五官重建。本模块不实施遗传画像；NIJ 相关介绍也提醒不能夸大从 DNA 生成准确个体外观的进展。[NIJ, 2015](https://nij.ojp.gov/library/publications/defining-face-what-can-dna-phenotyping-really-tell-us-about-unknown-sample)

信息少时，优先交付文字、局部特征示意或标记未知区域的轮廓图。宁可暂缓完整面部出图，也不要让绘图模型的默认五官变成新的“线索”。

## 2. 保护第一次回忆

NIJ 指南要求分别与各证人制作合成图，避免在制作前立即展示照片，先使用开放问题、避免诱导，并提醒证人不要猜测。College of Policing 托管的历史指引还区分了证人污染与操作者污染，强调操作者从证人处取得第一手描述。[NIJ, 1999, 第 II–III 节](https://www.ojp.gov/pdffiles1/nij/178240.pdf)；[ACPO/NPIA, 2009, 5.4–5.5](https://library.college.police.uk/docs/acpo/facial-identification-guidance-2009.pdf)

执行顺序：

1. **先保存，后追问。** 保存现有笔录、原始音视频或用户原文，分配证人和来源编号。逐字记录其不确定用语；“好像”不能改写为“确认”。
2. **先自由回忆。** 例如：“请按你自己的方式描述当时看到的这个人。记不清的部分可以说记不清，不需要补全。”不先展示生成脸、嫌疑人照片、其他证人画像或五官选项。
3. **再中性澄清。** 围绕已提到的内容问：“你提到眉毛，请说说你记得的样子。”必要时问“有看清眼睛吗？”并允许回答没有。不要问“是不是鹰钩鼻”“左脸是不是有疤”。
4. **记录观察条件。** 观察时间及距今间隔；持续多久；距离、光照、正面/侧面、运动、遮挡；是否戴眼镜等影响观察；证人与此人是否原先相识。记录证人是否看过照片、媒体、社交平台、其他人描述或生成图，以及接触顺序。未知条件写未知。
5. **证人之间保持独立。** 各自保存原始描述和版本。不要展示另一位证人的脸让其“确认”；不以人数多自动抵消证词相互影响。
6. **暂停条件。** 证人疲劳、痛苦、不愿继续或明确记不清时，保留已有信息并暂停；涉及特殊支持需求时转交受训人员。

认知访谈是需要训练的取证技术。College of Policing 的证据摘要支持适当使用情境回忆等方法，但这些方法不能保证每条细节正确；本 skill 的默认做法是自由叙述和中性澄清，不自行模拟复杂访谈技术或要求证人想象未曾看见的视角。[College of Policing, 2020](https://www.college.police.uk/guidance/obtaining-initial-accounts/strategic-recommendation-building-knowledge-and-skills)

**保持两条材料通道：**“证人记忆合成”与“影像可见特征记录”分别建立来源和版本。影像可以独立记录；不能拿影像、侦查假说或已知嫌疑人的五官去引导证人原本的回忆。历史英格兰和威尔士指引中的程序性要求不能直接当成其他辖区现行法律。

## 3. 建立逐项特征台账

台账在出图前完成，供绘图与复核共同使用。每条特征至少保留：

| 字段 | 记录要求 |
|---|---|
| 特征与描述 | 使用来源自己的措辞；必要时另列规范化描述，不能覆盖原话 |
| 来源定位 | 证人编号、原话及笔录段落，或原始影像文件、帧/时间码和可见区域 |
| 依据类型 | 直接回忆／影像可见／事后接触／未知；推测另列，不进入出图事实 |
| 可辨认程度 | 清楚／模糊／未观察，附原因；这是记录状态，不是正确率 |
| 原始确信表达 | 逐字保留；没有就写“未记录”，不让模型生成百分比 |
| 时点与可变性 | 观察日期；发型、胡须、眼镜、妆容等可能变化，不能默认至今相同 |
| 方向与视角 | “人物自身左侧”或“画面左侧”；是否镜像；不明就不定位到一侧 |
| 冲突与版本 | 与哪条来源不同；属于哪个证人、哪个修订版 |

可检查的范围包括整体轮廓、头发/发际线、眉、眼部、鼻、口唇、下颌、耳及有依据的独特标记。该清单只用于事后检查遗漏，不能变成要求证人逐项猜测的问卷。年龄感、肤色等若来自目击也须保留“看起来”的限定及观察条件；不得从犯罪类型或群体刻板印象补充。

**冲突不取平均。** 一位描述窄鼻、一位描述宽鼻时，保留两套描述，并检查是否看见同一人、视角或接触污染；不要合成一个“中等鼻子”来假装达成一致。只有来源确实支持两个候选解释时才出变体；无来源的随机脸不构成调查假说。

## 4. 从台账到图像

1. **决定交付层级。** 有多个直接可辨特征且来源可追溯时，可以出面部示意图；局部可辨时只画局部或对未知区域留白、遮罩；没有可用面部材料时输出取证问题，不出完整脸。
2. **只传递必要材料。** 给绘图工具的是已批准用于本次任务的特征及其编号，不传案情叙事、犯罪心理标签、嫌疑人身份猜测。原始案件材料的外发沿用本任务已有授权范围。
3. **按来源分版。** 默认先完成一个证人的一个基线版本。存在实质冲突时分别制作和标注；一次只比较有材料支持的少量变体，避免批量“挑一个像的”。
4. **保留整体关系。** 不把描述拆成互不相干的零件后声称能保证像本人。必要的布局仅是绘图选择，应在说明中与证据区分；不能自称复现了经验证的专业整体式合成系统。
5. **约束未知。** 未知部位留白或降低表达精度；不加无来源的痣、疤、皱纹、牙齿、耳形、饰物或肤色。若所用工具无法控制这些默认细节，退回文字或局部示意，不把成图作为合格画像。
6. **图像内标注性质。** 图面应有“目击描述合成示意图／非照片／身份未确定”或“影像可见特征示意／非原始影像”。标注证人/材料版本与未知部位；不能只在容易丢失的聊天文字里说明。

可交给绘图工具的约束示例（占位内容必须用实际台账替换）：

```text
用途：根据来源 W01 的原始描述制作调查用示意图。
表现：简洁、非照片式线稿；保持来源所述观察视角，不添加表情特征。
允许表达的特征：只使用台账 F01、F02、F03；每项与对应原话核对。
未知区域：U01、U02 以留白或遮罩明确表现，不补成具体五官。
方向：疤痕仅在来源确认的人物自身右眉外侧；无确认则不画位置。
不得增加：任何无来源的独特标记、心理暗示、犯罪场景或身份信息。
图内标注：目击描述合成示意图／非照片／身份未确定；版本 W01-v1。
```

合成方法、观察条件和延迟都会影响研究结果。Wells 等的实验发现某些特征式构建程序可能降低后续辨认表现；另一项使用贴近调查流程的实验未发现特征式或整体式构建对后续辨认准确性的正负影响。这些结果不支持“画像必然破坏记忆”或“AI 生成后必然更准”中的任一承诺。[Wells et al., 2005](https://pubmed.ncbi.nlm.nih.gov/16221034/)；[Pike et al., 2019，原始实验](https://pmc.ncbi.nlm.nih.gov/articles/PMC6724553/)

## 5. 图像增强与修订

**增强不等于恢复真相。** 保留原文件，在副本上做可记录的裁切、亮度等处理，并列出工具、版本、参数和每一步产物。噪声、压缩、模糊和视角限制必须随特征说明保留。完全丢失的信息不能被恢复为真实观察；生成式超分辨率补出的眼睛、疤痕等不可回填为原图证据。[SWGDE《Image Processing Guidelines》v1.0, 2016, 第 2、3、5 节](https://www.swgde.org/documents/published-complete-listing/15-m-002-swgde-image-processing-guidelines/)

一项 2026 年 DFRWS 初步研究对一个超分辨率系统及 50 张下采样面部图进行了测试，观察到独特面部特征被改动。它支持针对生成细节的审慎处理，不能据此计算本 skill 或所有增强软件的错误率。[Mazzei et al., DFRWS EU 2026 原始海报](https://dfrws.org/wp-content/uploads/2026/03/DFRWS_EU_2026_paper_123.pdf)

修订时先核对图是否忠实表达原始描述，再记录证人的反馈。分别保存：原始记忆中的细节、看图后提出的修改、无法判断的部分和出图错误。不能用“看起来更自然”覆盖原始特征；不能把证人看图后的新细节伪记为最初回忆。每次保存旧版、差异及来源；不因证人接受成图就声称身份得到独立确认。若重复看图后出现越来越具体、却无法说明原始观察依据的新细节，暂停迭代并标记潜在污染。

## 6. 交付与验收

最小交付包包含：原始描述与来源定位、观察条件、特征台账、未知与冲突、各独立版本、图内性质标记、处理/修订记录，以及下一步如何取得独立材料。下一步可以是寻找原始监控或另一个独立目击来源；不得以合成图“像某人”直接转成身份、罪责结论或自动对外发布。

以下为本项目的验收设计，**评估描述忠实度和流程完整性，不代表现实世界的识别准确率**：

| 检查项 | 可核查标准 |
|---|---|
| 来源完整 | 每条肯定性特征可回到原话或实际可见区域；来源覆盖率须完整 |
| 支持特征保留 | 有明确依据的特征均正确表达，或逐项说明未画原因 |
| 未知克制 | 未观察区域明确保留未知，无擅加独特标记；低清生成细节不升格为事实 |
| 冲突处理 | 不同证人/解释分开保存，无静默平均或择一后隐去另一方 |
| 方位一致 | 人物左右、画面左右、镜像和观察角度均正确，或明确未定 |
| 可追溯 | 版本可关联输入、台账、工具和修订；旧版可复核 |
| 表达性质 | 图内与说明均清楚标识示意、非照片、身份未确定 |
| 性能 | 记录端到端耗时、工具调用/出图次数；复用已核查台账，仅重绘实际变化部分 |

模拟盲测由独立保管的虚构案件材料给出可观察信息，执行模型只能看到公开给它的描述，评估端单独保存特征清单与情景真值。测试至少覆盖：无面部材料、模糊画面、单侧特征、方位歧义、证人冲突、事后照片污染及修订增加细节。评审检查台账与图像的实际内容，不能只检查提示词或模型自评分。逼真度、美观度、证人“觉得像”的评分均不能替代正确性；证明真实识别效果需要另外设计有对照、适当盲法和独立评审的研究。

## 7. 术语与来源的适用范围

NIST 的法庭艺术术语定义涵盖合成图、年龄变化图和面貌近似重建；这些任务不能混用。这里实施的是有来源的描述合成/可见特征示意，不是颅骨复原、年龄推演或身份比对。[NIST 法庭艺术术语条目](https://www.nist.gov/glossary-term/44251)

NIST/OSAC 2022-S-0008 涉及**面部影像比较的文档记录**；核验时页面标记为“在标准制定机构开发中”的提议标准。它不能为 AI 合成画像的准确性、身份识别或本模块提供认证。[NIST/OSAC 标准状态页](https://www.nist.gov/standard/906)

来源核验日期：2026-10-29。1999 年 NIJ 与 2009 年 ACPO/NPIA 文件作为历史方法来源使用；具体案件须核验当前适用程序。以上来源不应被表述为对本项目的认可或性能保证。

## 8. 本项目的可执行接口

Agent 先完成来源与语义核查，再按 [输入 Schema](../schemas/portrait-input.schema.json) 提取 `observations.json`。`kind` 是材料类型，不能为了通过出图检查把推测或旧画像标成直接观察。`none_reported` 表示检查材料后未报告污染，并不证明记忆无误；未了解接触史填 `unknown`，有风险填 `possible/known`。`context` 保存原始观察条件和帧/段定位；没有的信息不能补。保留所有相关来源，即使它们不能用于绘图。

最小的合成演示输入（不是实际案件）：

```json
{
  "case_id": "demo",
  "evidence": [{
    "evidence_id": "E1", "kind": "direct_witness",
    "source_id": "W1", "dependency_group": "W1-first-account",
    "statement": "初次独立笔录第2段：眉毛平直，鼻子没看清。",
    "contamination": "none_reported",
    "context": "正面观察；距离与持续时间未记录；未报告先看过照片或他人描述。"
  }],
  "observations": [
    {"feature_id": "eyebrows", "status": "reported", "value": "平直",
     "quotes": [{"evidence_id": "E1", "quote": "眉毛平直"}]},
    {"feature_id": "nose", "status": "not_visible"}
  ]
}
```

```bash
python scripts/detective.py portrait --case observations.json --out portrait.json --prompt-out portrait-prompt.txt
# 修订时保留全部旧证据，新增证据用新 ID，并在输入中填写 revision_reason
python scripts/detective.py portrait --case revised-observations.json --previous portrait.json --out portrait-v2.json
```

此接口只做确定性编译，不从自然语言自主识别人脸，不生成图片。它核查 ID/引文子串和上游引用，保守合并同来源、声明同组、复制文字和单上游 `derived_from` 依赖；多上游关系另用有方向的 `dependency_links` 保留，不能因后来一条回访受两份初始证词影响，就说两份初始证词互相污染。claim 的依赖组包含其上游涉及的全部组；不同分组不宣称独立。两条描述不同即暂停合并，Agent 需核对是实质冲突、同义还是互补，再保留有依据的版本。它**不验证引文是否语义支持特征、材料是否真实、人物是否同一、证人是否看清**；这些必须由 Agent 对照原件复核，不能称为脚本鉴定。

输出遵循 [规格 Schema](../schemas/portrait.schema.json)，始终 `analysis_stage=portrait_specification`、`render_state=not_generated`。没有可用面部特征则 `insufficient_information`；有待调和描述则 `clarification_required`；有可用面部观察且无冲突则 `specification_ready`，仅表示可以交付局部绘图请求，**不表示足以准确重建整张脸**。仅发型/胡须/眼镜/头饰/肤色/年龄感不触发面部出图。污染未知、污染已知、不确定描述、非直接观察及不合格上游不会进入绘图请求。它们仍保留在台账。

默认 `feature_sheet` 为各观察特征分开的局部示意；`partial_composite` 仍须将未报告区域留白/遮罩。绘图请求的 `source_panels` 按来源分开，保留各自观察条件及未知部位；多来源时强制特征页，不整合成一张脸。脚本不能自动判定多个来源是否同人：同一张图的输入应限于同一个人、一个连贯观察版本，证人记忆与影像版本分别运行；完整证据在案件账本保留。方位用人物自身左右，画面左右须先依据镜像/视角核对转换；未定则 `unspecified`，只能画不带侧位的局部，不能任意安放。视角未记录也只画局部，不把侧面观察擅自改成完整正脸。

收到有效 `render_request` 后，Agent 检查现有图像工具是否能执行相应任务，并按该工具的规则调用；不得声称调用未提供的工具。绘图前逐项复核 `feature_bindings`，不传犯罪叙事、心理标签或身份猜测。绘图后打开实际图片，逐项检查 `post_render_checks`，必要时去掉新增细节或退回局部图；不能仅以提示词内容验收。另存绘图记录，包含规格哈希、工具/版本、实际文件路径、出图耗时、检查结果与修订；不要把规格中的 `not_generated` 改成执行过的假记录。工具不可用则交付台账和绘图请求，明确图片尚未生成。

每次修订须使用独立输出路径。`--previous` 检查旧证据 ID 不被改写或删除，并记录旧版 SHA256、变化特征、移除/改写的旧主张和修订理由；它不判断修订更准确。不要把初次笔录和看图后的回忆混成一次观察。超过 200 条来源/200 条观察或总原文 40 万字符时明确拆案/定向提取，脚本拒绝超限，不静默截断。

画像专项的公开案情和隔离评分流程见仓库内的[盲测说明](https://github.com/MrBug1024/data-detective-skill/blob/main/test/portrait/README.md)；这些开发评测材料不包含在精简技能包中。
