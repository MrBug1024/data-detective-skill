# 面部特征与合成画像盲测材料

`cases.json` 提供六个完全虚构的案件请求与原始材料。每案只有 `case_id`、`request` 和 `evidence`；证据包含 `id/type/statement`。公开材料没有隐藏结局、目标真人照片或必须猜中的嫌疑人。

`private/rubrics.json` 是本地评测规范。它检查特征与原始观察的对应、引文是否真实、未知项是否为空、冲突是否保留、来源是否重复计权、绘图要求是否加入无依据细节，以及补证动作是否具体。它不以画像的逼真程度、审美或相似人脸命中率作准确性标准。

## 发送给被测 Agent 的内容

仅发送所选公开案件、实际 `SKILL.md`、其画像相关参考及公开的输出 Schema。不要发送本目录的私有评分文件、先前答卷、复核结论或命题的预期判定。画像输出按技能引用的 Schema，保持 `analysis_stage=portrait_specification` 与实际生成状态；这组材料本身不要求接入图像生成服务。

具备文件系统工具的 Agent 能够读到相邻 `private/`，文件夹名称不构成技术隔离。需要严格盲测时，将允许的公开案件、技能、参考、Schema及必要工具复制到独立临时目录，再让被测 Agent 只访问该目录。只靠范围指令的前向测试应如实标明是指令隔离，不能称作操作系统沙箱。

## 评分与复核

私有规范采用可审计的语义原子约束，不要求固定的中文措辞。`allowed_statuses` 表示在材料下可能合理的状态；即使状态枚举符合，也必须检查其条件，例如“可交付”是否仅指来源分开的特征页或局部合成说明。

- `feature_constraints` 检查一个特征的实际内容、状态、来源和越界扩展；多个语义可以由一条忠实的 claim 表达。
- `empty_claim_features` 检查没有材料支持的特征保持空，不允许根据常识、电影套路或默认人脸补齐。
- `source_dependency_sets/links` 表示转述或后信息污染关系，不能用文件数量代替独立观察数。混合来源记录可有多个上游，不能为了分组方便抹掉依赖。
- `render_constraints` 检查已知部分、未知部分和冲突变体的处理；有图像工具时，还须独立比较实际图像与特征说明，不能仅审查提示词。
- `must_check_actions` 检查补证动作是否指向具体材料和缺口，不奖励“继续调查”等空泛说法。

机器检查与独立语义复核分别记录。有效引文只证明“原文确实这样说”，不证明观察正确、证人独立、被描述者唯一或其实施了犯罪。对冲突、未知和受污染记忆的处理需要逐项复核。

保存实际输入清单、技能/参考版本哈希、原始答卷、执行日志、已生成图像及生成参数（如有）、逐项诊断和未验证范围。未生成图像时不得将规格通过写成“画像已经验证”；未取得原始影像时不得把文字描述当作已查看像素。模拟材料的通过数不构成真实案件准确率。

答卷可保存为 `P01.input.json`、`P01.portrait.json`、`P01.notes.md`（其余案号同理），分别是提取输入、脚本实际输出和 Agent 对用户问题/下一步行动的回答。使用 `--previous` 时另存对应的 `P01.previous.json` 供重放，并保留修订理由。此后运行：

```bash
python test/portrait/check_outputs.py --results test/results/portrait-forward --out outputs/portrait_validation/integrity.json
```

该工具不读取隐藏规范，仅检查原始 statement/ID 集合是否保持、输出是否能由编译器复现，以及回答文件是否存在。输出中的 `semantic_assessment=not_assessed` 提醒尚未验证语义；还须对照原始材料逐项独立复核。

私有文件仅供评测方在答卷完成后读取；不要让被测 Agent读取它来修订答卷。修订工作流后应保存新一轮答卷和版本，保留原始结果及评测分歧。
